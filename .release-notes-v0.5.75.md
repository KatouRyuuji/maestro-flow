## v0.5.75

### Overview

v0.5.75 hardens the knowledge v3 surface first introduced in 0.5.73–0.5.74:
Run knowledge candidates now carry a stable, deterministic fingerprint shared by
reconciliation and v3 promotion recovery, the store exposes v3 knowledge
transactions, the run knowledge-identity resolves explicit attribution
authority, the skill context declares the formal knowledge-governance policy
surface, and the installer preserves a prune restore-point so obsolete-file
removal is reversible. The dashboard gains Session/Run → wiki status adapters
for the virtual wiki surface, the sidebar workflow integration is updated, and
the release-machine source-phase certifier now spawns npm children
asynchronously with bounded concurrency.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.74...v0.5.75

### Features

- **Stable Run knowledge candidate fingerprints** (`751231b8`): `run complete`
  candidates get a deterministic Run-scoped identity
  (`runKnowledgeCandidateSnapshotHash`) shared by reconciliation and v3
  promotion recovery — frontmatter candidates shadow no already-staged
  candidate with the same ID, matching the review projection exactly.
- **v3 knowledge store transactions** (`751231b8`): `SessionV30KnowledgeStoreTransaction`
  exposes v3 knowledge mutations through the store transaction surface
  (`store.ts`), keeping completion receipts and knowledge-delta writes
  transactional.
- **Knowledge attribution authority** (`751231b8`): run knowledge-identity
  resolves the explicit attribution authority
  (`findKnowledgeAttributionAuthority` / `findSessionAttributionTarget`) for
  manual sources and search attribution on the active Run.
- **Formal knowledge-governance policy surface** (`751231b8`): the skill
  context now declares the policy contract — search/injection = exposure-only,
  explicit-load = consumed, record = explicit-attribution, completion =
  stage-candidates, promotion = explicit-review.
- **Installer prune restore-point** (`751231b8`): files an upgrade reinstall
  would prune are first preserved to a restore-point backup
  (`pruneBackupPath` / `obsoleteFilesPreserved`); manifest and tag-injector
  hardened.
- **Dashboard virtual-wiki adapters** (`751231b8`): Session/Run records map to
  wiki status entries (`sessionWikiStatus` / `runWikiStatus`); wiki-indexer
  fixes; maestro-sidebar `workflow.rs` integration updated.

### Refactors

- **Release-machine source-phase certifier** (`751231b8`): `runNpmChildAsync`
  spawns npm children asynchronously with bounded concurrency for streaming
  runners; session-run contract parity expectations updated to the new runner
  shape; release-machine test inline-node count expectation fixed (2 → 3,
  matching the build script's three `node -e` controls).
- **Fingerprint-stable candidate content** (`751231b8`): `reconcile.ts` and
  `atomic-write.ts` hardened — NFKC-normalized snapshot text, deterministic
  candidate identity, sha256-stable atomic writes.

### Gate hardening

- **Certified built-adapter graph kept yaml-free** (`7adfa7cf`): the WIP's
  `virtual-wiki-adapters.ts` imported `yaml`, which pulled the package's CJS
  internal `require()` edges into the built adapter's certified module graph and
  tripped `check:search-ranking-release-machine:built` at
  `UNDECLARED_ATTESTATION_LOAD` for `yaml/dist/compose/composer.js`. The handoff
  frontmatter parser was replaced with a light YAML-subset parser (dashboard's
  existing yaml-free convention, per `frontmatter-util.ts`) so the released
  package ships without that certification edge — same direction as the
  v0.5.69 plugin-engine boundary fix.

### Compatibility Notes

- No breaking changes: run/session file formats, commands, and the v3 surface
  are unchanged; additions are additive surfaces used from the 0.5.75 code
  paths.
- Prune restore-points are created only for files the reinstall would remove;
  existing installs are unaffected until the next reinstall/upgrade.
