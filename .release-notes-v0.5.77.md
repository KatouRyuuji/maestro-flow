## v0.5.77

### Overview

v0.5.77 removes obsolete Session/Run dispatch wrappers from the workflow
entrypoints. Commands that only need to load an execution document now invoke
the document directly, while explicit lifecycle operations continue to use the
Maestro CLI. The command mirrors, reference documentation, and workflow
instructions are synchronized with the current session/3.0 surface.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.76...v0.5.77

### Refactors

- **Direct workflow-document invocation** (`7fbff4b5`): issue, knowhow,
  knowledge, and spec command entrypoints no longer create a Session or Run
  merely to load their workflow documents.
- **Sessionless workflow metadata** (`7fbff4b5`): workflow documents remove
  retired `session-mode: inherited` and `run-mode` wrapper declarations while
  preserving direct lifecycle CLI paths for operations that need them.

### Fixes

- **Current lifecycle routing** (`7fbff4b5`): command dispatch text now matches
  the current session/3.0 execution model instead of recommending retired
  `maestro run skill` wrappers.
- **Visualizer command reference** (`7fbff4b5`): the brainstorm workflow now
  points to the current `maestro bv` visualizer command.

### Documentation

- **Mirror and reference synchronization** (`7fbff4b5`): Codex skill mirrors,
  command reference text, workflow guidance, and the generated docs reference
  now describe the same direct-document invocation behavior.

### Compatibility Notes

- Explicit `maestro knowledge` lifecycle commands remain CLI operations; this
  release changes how execution documents are loaded, not the underlying
  knowledge governance commands.
- Existing Session/Run records and the canonical session/3.0 runtime remain
  supported. The removed wrappers were only instruction-loading dispatch
  paths.
