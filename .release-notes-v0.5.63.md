## v0.5.63

### Overview

This patch release removes the vulnerable `sharp@0.34.5` runtime chain reported in
GHSA-f88m-g3jw-g9cj. Maestro now vendors the unmodified
`@huggingface/transformers@3.8.1` runtime and declares its production
dependencies directly, with `sharp` constrained to `^0.35.3`.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.62...v0.5.63

### Security Fixes

- Resolves CVE-2026-33327, CVE-2026-33328, CVE-2026-35590, and
  CVE-2026-35591 inherited through the bundled libvips dependency.
- The resolved runtime tree now contains `sharp@0.35.3`; the vulnerable
  `@huggingface/transformers -> sharp@0.34.x` package-manager edge is removed.
- The unmodified Transformers.js runtime is included under `dashboard/vendor/` with its
  source, license, and official tarball checksum documented in
  `dashboard/vendor/README.md`.

### Compatibility Notes

- Maestro's Node.js requirement remains `>=22.19.0`; `sharp@0.35.3` requires
  Node.js `>=20.9.0`, so no supported runtime is dropped.
- Transformers.js text embeddings and its Sharp-backed image decode path were
  smoke-tested with `sharp@0.35.3` / libvips 8.18.3.
- The vendored runtime increases the packed Maestro artifact by approximately
  10 MB. It should be removed once an upstream Transformers.js release accepts
  `sharp >=0.35.0`.
- Downstream packages that pin Maestro, including `pi-maestro-flow`, must bump
  their dependency to `maestro-flow@0.5.63` after this version is published.
