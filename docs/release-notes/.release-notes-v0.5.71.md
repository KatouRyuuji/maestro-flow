## v0.5.71

### Overview

v0.5.71 is the v3 simplification release: the Session/Run minimal protocol is now anchored on the ralph execution path, decision gates restore long-chain correction points, and two rounds of dead-weight removal cut the surface by ~1,700 lines. It also adds explicit writer switching (`maestro config session-schema set/show`) and writer-scoped capability declarations.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.70...v0.5.71

### Features

- **Decision gates for long chains** (`626d4334`)
  - Chain steps may declare a `decision_ref`; `session chain insert --decision-ref <id>` records an `open` decision on the Session.
  - `run next`/`run create` block on an unresolved predecessor gate (`DECISION_GATE_BLOCKED`, `next_actions: [run-decide:<point>]`); skipped predecessor steps do not gate.
  - `session complete` blocks on open gates; escalated gates pass but are recorded in completion `concerns`.
  - `run decide --verdict escalate` marks the gate escalated without pausing the Session — decision gates replace the paused lifecycle for correction points.

- **Config writer switching** (`69d784a9`)
  - `maestro config session-schema set/show` flips the workspace Session schema writer explicitly.
  - `capabilities --json` now declares writer-scoped `session_schema_writes` (e.g. only `session/3.0` under the v3 writer).

### Simplifications (ralph-run anchor)

- **Batch A** (`626d4334`): removed chain-proposal application (`--chain-proposal`/`--apply-proposal`), TC-P0-3 extra completion inputs (`--artifact`/`--note`/`--decision` and the `run/3.0` `notes`/`decision_records` fields), 22 retired v2-only subcommand stubs (16 `run` + 6 `session`), `session fail`, `session chain audit`, resume-map truncation (oversize projections now throw), and per-check knowledge reconciliation (candidates are generated once by `run complete`; `run check` only reads the persisted receipt).
- **Batch B** (`a826bb24`): dropped the participant entity and command family (`--participant` is still accepted for Pi-side injection compatibility and ignored), Session `identity_revision`, Session status `paused`, and the gates system (`gates_ref`, blocking-gate checks, `run.gate_refs`, `gates.json` creation). Receipts now store `participant_id = actorId`; the idempotency key shape is unchanged. Legacy `session/3.0` files with retired fields remain readable via strip-tolerant read schemas (`paused` maps to `open`; engine rewrites drop the retired fields). Migration maps paused targets to `open` and keeps legacy gates only in the read-only snapshot.

### Fixes

- `src/cli.ts` machine-mode whitelist and operation inference now cover v3 `decide`, `recall`, and `list` (G9 drift).
- v3 `run complete` summary falls back to `report.md` frontmatter when `--summary` is omitted.
- `run check` no longer writes knowledge-reconciliation receipts on read.
- Old v3 documents (with `identity_revision`/`gates_ref`/`participant_id`/`gate_refs`) read cleanly and are rewritten without the retired fields.
