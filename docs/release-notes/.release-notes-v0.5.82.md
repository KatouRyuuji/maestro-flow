# v0.5.82

## Overview

Promotes plan publishing to a first-class v3 producer Run and hardens the
hook/MCP/manifest surfaces that quietly degrade under load: plan authorship
now runs through the canonical session/3.0 + run/3.0 lifecycle, hook errors
are centralized into a never-throwing JSONL sink with a statusline alert,
MCP tool access is enforced through a single shared policy snapshot, and
manifest cleanup preserves user edits while still removing stale Maestro
sections.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.81...v0.5.82

## Highlights

- **Plan publish as a v3 Run**: `plan` opens a Session with an inline chain step and publishes through run-v3, giving plan authorship the same authority, identity and recovery semantics as any other Run.
- **Centralized hook logging**: hook errors/warnings land in `~/.maestro/logs/hooks-error.log` (rotation + never-throw + MAESTRO_DEBUG echo), and the statusline renders a `⚠N` alert for unread errors.
- **Unified MCP tool access**: ListTools and CallTool share one immutable policy snapshot, so a hidden-but-registered tool can no longer be invoked by guessing its name.
- **Manifest cleanup correctness**: markers prove section ownership, not file ownership — mixed user+Maestro files have their Maestro sections removed while user content outside the markers is preserved.

## Compatibility Notes

- Plan publish now requires the session/3.0 + run/3.0 lifecycle; Execution-era lease and legacy v2 paths are rejected at the coordinator fence. Hosts that injected a divergent actor for plan authorship are rejected (`participant == actor`).
- MCP hosts that relied on calling a registered-but-unlisted tool by name now receive an `isError` response without the handler being invoked. List the tool in `mcp.enabledTools` (or `MAESTRO_ENABLED_TOOLS`) to expose it.
- Hook errors no longer print to stderr by default; set `MAESTRO_DEBUG=1` to restore the developer echo, or read `~/.maestro/logs/hooks-error.log`.
- Manifest cleanup of a mixed user+Maestro file now removes the Maestro sections instead of preserving the whole file; user content outside the markers is always kept.
