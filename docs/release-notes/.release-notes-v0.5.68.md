## v0.5.68

### Overview

v0.5.68 修复 Run 完成流程的路径基准陷阱：`--evidence` / `--artifact` / `--chain-proposal` 的相对路径按契约以 Run 目录解析，现在无歧义接受落在 Run 目录内的 shell-CWD 相对路径，报错显式给出解析基准与解析后路径；同时修复 Windows 跨盘符 containment 绕过。技能层（verify / execute / odyssey-review）的证据语义同步对齐「失效条件驱动 + 强制证据复用」，抑制门禁触发的整矩阵反复验证。

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.67...v0.5.68

### 🐛 Bug Fixes

- **Run 完成路径解析**（`src/run`）：
  - `fix(run)`: resolve evidence/chain-proposal paths with CWD fallback and explicit base — `discoverExtraArtifacts` 与 `selectChainProposal` 在 run-相对目标缺失且 CWD 解析无歧义落在 Run 目录（proposal 为其 `outputs/`）内时采纳 CWD 读数；两处报错现在包含解析后绝对路径、Run 目录基准与修复指引；修复 Windows 跨盘符潜在绕过——`path.relative()` 跨盘返回绝对路径而非 `..`，旧 containment 检查会误判为「在 outputs/ 下」（`fc711ec1`）

### 📝 Behavior / Skill Docs

- **验证纪律对齐**（`prepare/`、`workflows/`）：
  - `docs(prepare)`: align skill-layer verification with evidence-reuse discipline — verify 铁律从「fresh evidence」改为「grounded evidence」：本轮 live run 或同 revision 仍有效的 live-run 结果均可作为证据；定义 material invalidator 正/反面清单（时间流逝、阶段/gate 转换、agent 切换、无关编辑不构成失效）；要求最窄可执行目标，全仓范围仅当 criterion 本身要求；execute self-check 限定为本次改动的 scoped smoke（never repository-wide matrix）；odyssey-review 新增 S_FIX/S_CONFIRM 证据复用不变量——tier 提交只失效覆盖该提交的测试，禁止因 tier 推进重跑全矩阵（`e1aed8fb`）
  - `docs(workflows)`: run-mode 封存程序新增 evidence path base 条款；command-authoring 的 `session done` 模板标注路径基准与 CWD 兜底语义（`3b3277e7`，基准条款随 `fc711ec1`）
