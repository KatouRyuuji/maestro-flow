# v0.5.81

## Overview

Closes the Session/3.0 surface around Execution-era residue and hardens run-v3 lifecycle correctness: `participant=actor` identity is enforced on lifecycle mutations, chain update and structured continuation commands land in the canonical command graph, decision gates route before chain continuation, recovery mutations and return continuations are fenced, v3 CLI run errors normalize with stable migration guidance, and `maestro-next` infers lifecycle from the canonical Session state.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.80...v0.5.81

## Highlights

- **Session/3.0 surface closure**: Execution-era surface removed from the canonical command graph; `participant=actor` identity enforced; `chain update` and structured `continuation` commands added.
- **run-v3 decision-gate ordering**: decision gates now route before chain continuation, so a pending decision resolves before the chain advances.
- **run-v3 recovery fencing**: recovery mutations and return continuations are fenced to their owned step — a failed or recovering Run no longer mutates state outside it.
- **v3 CLI error normalization**: legacy commands report a single actionable error with the canonical replacement and migration guidance.
- **maestro-next lifecycle inference**: the router reads the authoritative Session entity instead of heuristic or stale signals.
