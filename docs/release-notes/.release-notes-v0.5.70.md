## v0.5.70

### Overview

v0.5.70 delivers the next Session/Run protocol generation and the infrastructure needed to adopt it safely. It introduces `session/3.0`, `run/3.0`, and `run-response/1.2`; independent identity, orchestration, activity, and per-Run revisions; participant identities; immutable request and transition receipts; deterministic context resolution; atomic chain advancement; and a bounded resume projection. The CLI now selects the v2 or v3 command tree from the workspace writer and exposes strict machine-readable capabilities and help catalogs.

The release also includes the Session/Run 2.0 Execution foundation, knowledge reconciliation and transcript evidence, Pi agent streaming and persistence improvements, dashboard workflow visibility, and the Maestro Sidebar desktop application developed in this repository. Maestro Sidebar remains independently versioned and was released separately as `sidebar-v0.1.1`.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.69...v0.5.70

### Features

- **Session/Run v3 minimal protocol** (`d03d1640`, `e8e2f221`)
  - Adds strict `session/3.0` and `run/3.0` schemas with separate identity, orchestration, activity, and per-Run revision boundaries.
  - Adds participant registration, immutable `request-receipt/2.0` and `transition-receipt/2.0`, replay-safe mutations, atomic Run completion and chain advancement, deterministic context selection, and compact `ResumeMapV1` projections.
  - Adds v3 migration from legacy Session/Execution authority, including source-byte hashes, legacy transition-history projection, retained audit state, and secret redaction.
  - Keeps v2 mutation behavior intact and fails closed when a workspace selects the v3 writer.

- **Strict v3 CLI and protocol discovery** (`e8e2f221`)
  - Routes `session`, `run`, `participant`, and retired `execution` commands according to the workspace writer.
  - Adds `run-response/1.2`, v3-aware `maestro capabilities --json`, and `maestro help --json` command catalogs.
  - Preserves normal `maestro help <command>` behavior and supports both `--workflow-root <path>` and `--workflow-root=<path>`.
  - Returns structured replacement guidance for retired Execution commands in v3 workspaces.

- **Execution and knowledge lifecycle foundation** (`2fac28c5`, `b5081dec`, `3f027962`, `0978d4b8`, `b4513a70`)
  - Adds Session/Run 2.0 Execution state, leases, handoff, generation-bound Runs, response 1.1 envelopes, reuse acceptance, and source-fenced recall.
  - Adds reconciliation schemas, Session-source knowledge promotion, transcript evidence snapshots, and hardened promotion/review commands.
  - Aligns command, workflow, guide, and release-machine contracts with Execution authority.

- **Dashboard, Pi agents, and Maestro Sidebar** (`616c93c3`, `ea9cd0ff`, `88f85ee2`, `ddd78504`)
  - Adds Maestro status routes, workflow monitoring, Pi adapter streaming and persistence, agent lifecycle visibility, and higher-frequency knowledge refresh.
  - Adds the independently versioned Maestro Sidebar Tauri application with workflow monitoring, knowledge management, editor/preview surfaces, themes, workspace switching, and release automation.
  - Adds the dashboard reminder and canonical Sidebar download links. Sidebar artifacts are published through the separate `sidebar-v*` release channel.

### Bug Fixes

- **Run/chain recovery closure**: failed Runs now mark their active step failed, cancelled Runs requeue it, retry lineage and attempt values derive from authoritative source Runs, and completed/skipped/failed steps can no longer be rewritten through pending-only chain mutations.
- **Participant replay correctness**: participant mutations now use Session-scoped immutable receipts; replay returns the original result and conflicting participant, operation, or payload reuse returns `REQUEST_CONFLICT`.
- **CLI routing and help compatibility**: fixes equals-form workflow roots selecting the wrong command tree, preserves Commander help, and makes compound Run completion explicitly require `--advance`.
- **Legacy migration audit coverage**: Execution transition records are included in migration source hashes and sanitized audit projections without lease, handoff, or private token material.
- **Session/Run contract hardening**: fixes dead consume aliases, optional reuse handling, skipped-step checks, review repair routing, missing-Session guidance, and Execution lease replay behavior.
- **Sidebar interaction and accessibility**: fixes connection recovery, editor status and focus behavior, modal focus trapping, narrow layouts, markdown table rendering and injection fallback, completion feedback, and disabled/pressed state coverage.
- **Dashboard Wiki and ranking release reproducibility**: updates the canonical runtime fixture to satisfy strict review-findings verdict metadata and verdict-based completion; isolates source-selection checks from filesystem cache timing; and replaces ignored production knowhow dependencies with tracked lifecycle fixtures so clean clones exercise the same Pi ranking proofs. The focused Windows gate uses a local 15-second test budget without weakening assertions.
