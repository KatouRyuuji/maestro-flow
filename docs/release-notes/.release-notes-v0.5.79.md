## v0.5.79

### Overview

v0.5.79 is a small Windows-only follow-up to v0.5.78: it adds `windowsHide: true`
to the six `detached: true` spawns that were missing it, so background workers no
longer flash a CMD console window on Windows when the host process chain has no
attached console. Behavior on POSIX is unchanged.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.78...v0.5.79

### Fixes

- **Windows detached-spawn console flash** (`47a62ef7`, #25): on Windows, a
  `detached: true` child that inherits no console from its parent causes Windows
  to allocate a **new console window** for the child when the whole parent chain
  has no visible console (GUI hosts such as Orca, VS Code extensions, or any
  detached terminal daemon). The child runs for a few hundred milliseconds
  (daemon bootstrap) and the window then disappears — perceived as a CMD window
  "flashing" on every `maestro hooks run` / `maestro search` invocation after the
  30-min idle self-shutdown. Added `windowsHide: true` (`CREATE_NO_WINDOW`) to
  the six detached spawns that were missing it, aligning them with
  `src/hooks/kg-sync-hook.ts` which already guarded its spawn. POSIX ignores the
  flag.

### Compatibility Notes

- Windows-only behavior change: background workers that previously flashed a
  console window now run with no window. `detached: true` + `unref()` semantics
  are unchanged; this is purely the missing console-suppression flag.
- macOS/Linux: `windowsHide` is ignored, so there is no behavioral change.
