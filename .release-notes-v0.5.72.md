## v0.5.72

### Overview

v0.5.72 closes the cross-repo audit round: 12 core-side findings from the peer review are fixed together with the atomic knowledge-loop staging fix, the deterministic Run-ID replay contract, and the release-machine proofs. The reference design now marks the v2 canonical prompts/gates as planned transitions (phase 4) and the remaining blockers are the v3 birth/brief injection and packaged-consumer E2E.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.71...v0.5.72

### Fixes

- **Atomic knowledge staging** (`33a6583f`): `run complete` stages knowledge candidates into the knowledge-delta inside the same transaction as the completion receipt — candidates become visible to `maestro knowledge review` immediately; `summarizeSessionKnowledge` reads are schema-agnostic.
- **Predecessor publication authority on `run create`** (`4039bccc`): Run shells are created only after the predecessor publication authority passes; replay candidates clear engine-injected `input_refs`.
- **Participant identity hardening** (`4039bccc`): transition receipts force `participant_id = actor_id`; migration completes request receipts; `--participant` is accept-and-ignore for injection compatibility.
- **ResumeMap cleanup** (`4039bccc`): core ResumeMap drops the retired `identityRevision` and `paused`; the forbidden-word check rejects any execution field.
- **Decision-gate binding** (`4039bccc`): resolved/escalated decisions can no longer be bound as a new gate.
- **Deterministic Run-ID replay** (`b3a6f22c`): `run next` without `--run` derives the Run ID from the request ID (`run-<sha256(request-id) prefix>`), so retrying a lost response with the same request ID replays the original mutation instead of hitting `REQUEST_CONFLICT`.
- **Canonical artifact flag** (`d762f143`): `--expected-session-revision` is retired in favor of the canonical `--expected-orchestration-revision`.
- **Release-machine proofs** (`8842a3a1`, `a6bd2a2f`): dropped the retired `use-participant-status` assertion and aligned the v3 proof sequence with the open-revision-1 orchestration contract — all 30 build-backed proofs pass.

### Docs

- Reference design `§13`/`§14` updated by the peer review: Pi coordinator/ResumeMap/response binding and the deterministic Run-ID are confirmed fixed; v2 canonical prompts, agents and gates are explicitly marked as planned phase-3/4 transitions; remaining blockers converge on birth packet, brief Resume Packet, packaged executor, model/migration and real cross-repo E2E (`b3a6f22c`).
