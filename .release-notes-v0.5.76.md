## v0.5.76

### Overview

v0.5.76 hardens knowledge governance across session/1.x, session/2.0, and
session/3.0. A broken session-source candidate is now fenced independently:
it remains visible as blocked, `promote --all` skips it, and healthy candidates
can still be promoted. Statusless session/2.0 reconciliation, resolution, and
mixed-origin promotion now use transactional sidecar writes without rewriting
`session.json`. Canonical v3 paths reject retained legacy Execution authority,
and transcript evidence snapshots move onto the restricted v3 knowledge
transaction surface.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.75...v0.5.76

### Features

- **Per-candidate reconciliation fence** (`b07a1261`): session-source
  candidates that fail immutable-source revalidation are recorded as
  `status: blocked` with an operator-facing reason. Review keeps them visible,
  explicit promotion fails with that reason, and `promote --all` skips them
  while promoting unrelated healthy candidates.
- **Transactional transcript evidence for v3** (`b07a1261`): transcript
  snapshots use `SessionV30KnowledgeStoreTransaction` with a restricted
  content-addressed path and open-Session lifecycle check. Identical quotes
  from distinct host entries retain independent locator-bound snapshots.

### Fixes

- **Statusless session/2.0 knowledge transactions** (`b07a1261`): Run and
  Session reconciliation persistence, inline resolution, and mixed-origin
  promotion now commit through one knowledge transaction. Run and Session
  sidecars move together while canonical `session.json` remains byte-stable.
- **Receipt refresh and promotion fences** (`b07a1261`): inline resolution
  refreshes its receipts before committing the human decision; final promotion
  revalidates candidate sources and corpus state under the store lock.
- **Canonical v3 authority boundary** (`b07a1261`): v3 reads fail closed when
  retained legacy Execution storage is present instead of treating it as
  canonical authority. Knowledge stage/record on valid v3 Runs no longer reads
  legacy Execution state.
- **Legacy governance timing** (`b07a1261`): reconciliation, resolution, and
  promotion refuse while a legacy Execution remains open and now direct the
  operator to seal its Runs and the Execution before retrying.
- **Stable blocked receipt freshness** (`b07a1261`): diagnostic wording is no
  longer part of the immutable freshness commitment, so platform- or
  path-specific error text cannot stale healthy peer candidates.

### Gate Hardening

- Focused release-machine Vitest proofs now set explicit 30-second test and hook
  limits. Added regression coverage for statusless Run/mixed-origin promotion,
  per-candidate blocking, v3 retained-Execution refusal, v3 transcript evidence
  transactions, and post-migration canonical authority.
- The search-ranking source certificate now classifies `PRODUCTION_ARTIFACTS`
  as full-phase generated outputs. A fresh checkout can run the source gate
  before build without requiring stale `dist/` files, while the built phase
  still certifies every production artifact.

- Source-only knowhow lifecycle tests use the TypeScript lifecycle implementation
  when the compiled worker is not available. Published builds still prefer the
  colocated JavaScript worker, preserving worker isolation for consumers.

### Compatibility Notes

- Receipt additions are backward-compatible: successful session-source entries
  may omit `status` and continue to parse as the legacy successful form.
- Existing session/1.x workflows remain supported. Knowledge governance that
  targets a legacy Session with an open Execution must wait until that
  Execution is sealed.
- session/3.0 remains authoritative. A migrated v3 Session with non-empty or
  symlinked legacy `executions/` storage fails closed until the invalid retained
  state is resolved through the supported migration/recovery path.
