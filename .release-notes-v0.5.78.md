## v0.5.78

### Overview

v0.5.78 adds a read-only defensive-programming risk audit mode to Odyssey, makes
the knowledge graph's call edges usable for per-function impact analysis, and
hardens knowledge-graph auto-init reliability. The knowledge governance prompt
sections are slimmed and the `knowledge stage` command now prints a run-less
fast-path next-step card.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.77...v0.5.78

### Features

- **Odyssey defensive mode** (`b7ba9907`): new read-only `--mode defensive`
  business-anchor-driven risk audit. It takes business-critical outcomes as
  anchors, backward-slices to their supporting code, and forward-propagates
  risk through the call graph. The state chain
  `S_INTAKE → S_ANCHOR → S_SLICE → S_SCAN → S_PROPAGATE → S_REPORT` reuses the
  shared back-half (no `S_FIX`/`S_CONFIRM`). It scans eight defensive patterns
  (broad catch / exception swallow / default value / null fallback / clamp /
  silent convert / duplicate constraint / duplicate default), classifies
  exceptions A/B/C/D, scores risk `R = S × P × B × H`, and emits a §14
  severity-matrix report (`DEF-NNN` with the full propagation chain). Findings
  route to `--mode improve` (fix) or `--mode debug` (root cause). Tiers
  `quick`/`standard`/`deep` and `--sink-depth 1|2|3|all` control scope. The
  command reference and usage guide now describe seven Odyssey modes
  (debug|improve|planex|review|security|defensive|ui).
- **Knowledge stage run-less next-step card** (`d6ba5763`): `knowledge stage`
  (session source) now prints a next-step card that covers the review
  presentation protocol, supersede/conflict entry maintenance, and
  evidence-freshness timing, plus a fast-path note: a standalone insight that
  needs no Run/Session binding can be written directly with
  `maestro knowhow add --type <type> --title "<title>" --body-file <path>` — no
  `--evidence`, no promote cycle. `knowledge promote` errors hint the
  `--as unique` + `maestro spec supersede <old> --by <new>` fallback, and a
  successful promote that replaces an entry prints the spec-supersede
  evolution chain.

### Fixes

- **KG call-edge attribution** (`108ed99f`): call edges are now attributed to
  the enclosing function instead of the file node, so per-function
  callers/callees/impact traversal (backward slicing, forward-propagation
  radius) works for the defensive audit and any per-function impact analysis.
  Module-level calls without an enclosing function still fall back to the file
  node. Added a dedicated `code-resolver` test suite.
- **KG auto-init FileLock re-entrancy deadlock** (`7ffbcd6b`): the
  non-re-entrant `FileLock` that wrapped both `MaestroGraph.init()` and the
  subsequent `sync` deadlocked auto-init (it hung ~30s then failed, leaving a
  created-but-unsynced DB). The lock now wraps only `MaestroGraph.init()` while
  `sync` runs under its own lock, so auto-init completes in ~470ms.
- **KG auto-init high-severity defects** (`f462f985`): 7 high-severity
  init-path defects fixed across `connection`, `db/index`, `migrations`,
  `engine`, `orchestrator`, `sync-state`, `kg-auto-init`, and `kg-sync-hook`
  (168 insertions / 32 deletions, 8 files).
- **KG auto-init medium-severity defects** (`a9cdb855`): 8 medium-severity
  init-path defects fixed in `orchestrator` and `sync-state` (concurrent-init
  FTS corruption guards).
- **KG auto-init low-severity defects** (`268cfa4d`): symlink-loop and
  remaining low-severity defects fixed in `code-extractor`.

### Refactors

- **Knowledge governance prompt slimming** (`362720f1`): workflow
  knowledge-governance prompt sections are slimmed — Run Knowledge Invariants
  compressed 7 → 5 rules and Governance Boundary folded to one bullet. Command
  syntax, presentation-protocol detail, and error-branch guidance are now
  injected at runtime (stage card, promote hints, review next/resolve lines)
  instead of per-session static text across the claude/codex/agy mirrors
  (27 insertions / 42 deletions).

### Documentation

- **Command reference and inventory** (`b7ba9907`): `docs-site` command
  reference and `inventory-v2.json` updated to describe seven Odyssey modes;
  `command-usage-guide.md` documents the defensive mode (English + Chinese).
- **Changelog page** (version-prep): `ChangelogPage.tsx` carries the v0.5.78
  entry with the five changes above (EN + ZH).

### Compatibility Notes

- The defensive mode is **read-only**: it adds no `S_FIX`/`S_CONFIRM` states and
  writes no fixes; existing Odyssey modes (`debug`/`improve`/`planex`/`review`/
  `security`/`ui`) are unchanged.
- KG call-edge attribution is backward-compatible for file-level traversal
  (module-level calls still attribute to the file node); per-function traversal
  gains fidelity it did not have before.
- The auto-init deadlock fix changes only the locking decomposition around
  `init`/`sync`; the created DB schema and sync semantics are unchanged.
- The slimmed knowledge-governance prompt text is a presentation refactor; the
  stage → review → promote lifecycle, the direct-write whitelist, and the
  evidence requirements are unchanged.
